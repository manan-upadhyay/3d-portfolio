## 1. Design-direction decisions (owner-approved)

Four open design questions were put to the owner with options; the chosen
directions below are binding for this pass.

| Topic | Decision | Rationale |
|---|---|---|
| Arsenal core stack (desktop) | **"Luminary suns"** — keep the category orbits; primary-tier tools render as larger glowing suns with a breathing corona + always-lit labels; secondaries are dimmer moons; a one-line legend explains brightness = mastery | Least structural churn; the metaphor (brightness = mastery) rides the existing solar-system theme instead of fighting it |
| Projects ("The Realms") | **Proof-first plate** — name + one lead outcome line + a 3-cell proof strip (role · outcome · scale) + restored tech pills + CTAs; full description + all highlights collapse behind one "The full story" disclosure | The section must read in ~5 seconds for a skimming recruiter, with the depth one tap away — cuts visible text ~60% without losing any proof |
| Commit graph | **Reframe to the real build window** (dense weeks, not a sparse 53-week year); mobile starts at the latest week; stats recomputed for the window | See §2 pushback — faking was refused |
| Observatory + Codebase Atlas on mobile | **Bespoke mobile modes** — Observatory: an auto-cycling "signal readout" card (one real event at a time, tap to advance) + metric strip, no orbit/chips; Atlas: hotspots-first cards with their "why", full tree behind a disclosure; desktop keeps both, slimmed | The proof survives on the majority-mobile audience instead of being hidden; honors §11.3 (dedicated mobile experience) |

Decisions made under owner-delegated judgment ("give me options / decide"):

- **Hidden features (Field Guide):** icon + title grid only; the "how" opens on
  tap/click as an inline reveal (one open at a time). The cards therefore become
  *real* buttons — which also resolves the "fake hover" complaint honestly:
  affordance now signals a genuine interaction.
- **Expedition truncated values:** tap-to-expand in place (the cell un-truncates
  and wraps; tapping again collapses). Chosen over a popup: it's the lightest
  industry pattern (iOS Settings-style), needs no new overlay, and works with
  one thumb. Desktop gets `title` tooltips for free.
- **Locked persona on phone (expedition constellation):** tapping a sealed star
  now opens the shared `ClueUnlock` input inline (same component as the Voice
  Hall / mobile drawer), so the keyboard path exists everywhere. Tapping an
  unlocked star updates the group heading to the persona's name (the "title
  never changes" complaint).
- **Deployed/eliminated ledger (mobile):** entries show the title with the
  rationale clamped to one line; tapping a row expands it. The affordance is a
  small rotating `+` glyph on the row — not a column of accordion chevrons.

## 2. Pushbacks & owner-facing responses

1. **"Should we lie about the commit graph and push it to be ideal?" — No,
   refused.** The audience this page exists to convince is developers and CTOs;
   the public repo link sits next to the graph, and GitHub's own contribution
   view would contradict a fabricated grid in one click. That's not a design
   risk, it's a credibility kill — the exact trust the v1.1 Restraint Pass was
   built to recover. The honest reframe (crop to the build window) actually
   *looks better*: every visible square is dense and real, and the story becomes
   "this site was built in an intense, focused burst," which is true and
   impressive.
2. **Removing the Reckoning ("revision") section** — done as asked, but its
   closing CTA (contact + résumé) was **kept** and moved to the end of the page.
   The making-of page must still end on an ask (v1.1 Workstream B: no dead-end
   pages); deleting the section's content is fine, deleting the page's only
   conversion exit is not.
3. **Removing the fixed wordmark** — done as asked. Note for the record: it was
   added in v1.1 because beta users mistook the map icon for a logo. If Beta 3
   resurfaces "who is this site about?" confusion mid-page, the answer will be a
   brand mark again (possibly scroll-aware in the SideRail rather than a fixed
   overlay), not more copy.
4. **Pills** — agreed, and the Codex was wrong to ban the *pattern*. Pills/chips
   predate AI (Bootstrap badges 2011, Material chips 2014) and are core web
   vocabulary. The rule is rewritten (§4 below) to target what actually signals
   AI: *default-styled, uniform, decorative* chip rows — not the existence of
   pills. Functional/branded pills are explicitly allowed again.

## 3. Known limitations & platform notes

- **iOS input auto-zoom:** Safari zooms when a focused input's font-size is
  <16px. Fixed by enforcing ≥16px on all text inputs on coarse-pointer devices
  (CSS). We deliberately did **not** add `maximum-scale=1` to the viewport meta:
  it suppresses pinch-zoom for users who need it (WCAG 1.4.4).
- **Making-of menu transparency (iPhone):** the sheet relied on a heavy
  `backdrop-filter` for legibility; iOS Safari drops the filter in some
  compositing situations (observed on `/making-of`), leaving a translucent pane.
  Fix: the sheet/cards are now near-opaque by default, with blur kept as a
  progressive enhancement — legibility no longer depends on a fragile filter.
- **Gyro physics:** iOS requires a user-gesture permission prompt for
  `deviceorientation`/`devicemotion` — the "tilt to explore" button stays as the
  gate on iOS. Tilt now drives the full gravity vector (marble-on-a-tray,
  calibrated to the holding angle when enabled) and `devicemotion` shake adds a
  real impulse (jump), with speed proportional to tilt rate. Without permission,
  drag-and-fling physics still work.
- **Astrolabe loudness (iPhone vs Mac):** there is no reliable per-device output
  calibration on the web; the fix is a fixed attenuation of the gear/watch bed on
  coarse-pointer devices (phone speakers sit closer to the ear and compress
  differently). If it still runs hot on specific handsets, the next lever is a
  lower `GEAR_FULL_SPEED` mapping, not more attenuation.
- **Commit history data:** `src/constants/commitHistory.js` is regenerated from
  `git log` in this pass (was stale at 2026-07-01). It must be regenerated at
  release time — every square is real, that's the whole point.

## 4. Rule changes (Codex + standards)

- **[common-ai-signs.md](common-ai-signs.md)** — pill/chip rule normalized. New
  wording: the tell is *"uniform default-styled chip rows used as decoration"*;
  the human move is *"pills that carry function or brand styling (selected
  state, real taxonomy, on-palette tokens) are normal web design and allowed."*
  Same reframe for the eyebrow: an uppercase kicker with a leading rule is a
  classic editorial device — the tell is only when it's *identically repeated,
  default-tracked and content-free*. Ours is restored (see §5) with the
  site's own tokens and story-bearing content.
- **Eyebrow restore:** the `main`-branch `.chapter-eyebrow` treatment (uppercase,
  0.32em tracking, 28px leading rule in the map-line gradient) is restored
  site-wide — experience cards, contact form ("The Message"), correspondence
  card, expedition titles, and the Atelier act/sub labels.

## 6. Owner follow-up observations (mid-pass, applied)

### Round 1

1. **Project stack pills → reverted** to the mono dot-line: with the proof strip
   on the plate, pills tipped the card into congestion (A5 updated above).
2. **Arsenal corona ring → replaced** with a breathing glow on the node's own
   disc: the detached ring sat visually off against the labels (D3 updated).

### Round 2

3. **Lens ignores gravity in DevTools** — root cause: gravity switched to the
   tilt vector the moment sensor *listeners* attached, even when no data ever
   arrived (emulators). Now a `gyroLive` flag flips only on the first real
   orientation event, and the tilt physics were made *honest*: no calibration
   trick — `g·sin(beta)` / `g·sin(gamma)` of the actual device angles, so an
   upright phone pulls the ball down-screen and a flat phone lets it rest.
4. **Duplicate closing CTA on `/making-of` removed** — the shared Layout footer
   renders directly below it with the same ask; two identical button rows
   back-to-back was noise. (`atelier.cta.*` keys removed from all 5 bundles.)
5. **Dawn/day control colors re-graded** — the mobile dial's liquid in light
   themes is now the loved "sound is live" ember-peach wash (independent of the
   sky hue, which turned it muddy); `--sky-dawn`/`--sky-day` swatches freshened
   (`#E58F70` / `#EFA93F`) for the wheel arc and sky menu.
6. **Desktop sound control now morphs INTO the bar** — the old popover stacked a
   second dial (two speaker icons). The circle itself expands into the capsule:
   same white-bordered pill, an ember liquid rising to the level on the jelly
   spring, drag to pour, the one icon stays put (click = mute/unlock as before).
7. **Experience scroll lag fixed** — the strip's *static* `data-lenis-prevent`
   made the whole band a vertical dead zone (Lenis ignored deltaY over it). The
   attribute now toggles per wheel event by dominant axis: sideways → timeline,
   vertical → page. The pendulum-sway rAF loop is also gated to viewport
   visibility and skips settled writes (no idle per-frame cost).
8. **"Can't see the core highlights" → a real pre-existing bug found**: the
   orbital node discs NEVER rendered. `.realm-card` (later in the cascade)
   silently overrode Tailwind's `absolute` (and `rounded-full`) on the disc
   span, collapsing it to 0×0 since the section shipped — every node was a bare
   logo. Position/inset/radius are now inline; all discs render, and the five
   core "suns" (React, Next.js, TypeScript, Node, Express) carry an ember wash,
   ring, breathing glow, and always-lit label.

### Round 3

9. **Sound button's inner circle off-center** — the fixed 48px button overflowed
   the bordered capsule's 46px content box under `overflow:hidden`, shifting the
   wash circle ~1–2px. The button now sizes itself from the content box
   (`inset-x-0` + `aspect-square`); centering verified pixel-exact via CDP.
10. **Mobile contact form un-carded** — on phones the Message panel sheds the
    realm-card chrome and runs full-width (`.contact-plate`; the card returns
    from `sm:` up). More room for the fields, and the form reads as its own
    scene. The Correspondence card stays a card (a distinct object).

### Round 4

11. **Proof strip → bare field-notes.** The boxed Role/Outcome/Scope grid read
    as a spec table (and forced awkward taxonomy — "Scope: live preview" isn't
    a scope). Now three label-free facts, each opened by a quiet ember dash,
    in the plate's own editorial register. `works.proofLabels` removed from
    all 5 bundles; the `proof` values in constants stand alone.
12. **Mobile contact zebra.** With the card gone (round 3) the form blended
    into the projects above. Owner's direction implemented: on phones the
    Message form and the Expedition recap are **full-bleed surface bands**
    (edge-to-edge, no radius, theme card-tint so dark mode works — not
    hardcoded white) and Correspondence is the **bare beat** between them.
    The alternation separates the scenes and returns the card padding to the
    content. Desktop keeps the cards. Verified: zero horizontal overflow.
13. **Persona walkthrough audit** shipped:
    [reports/audit/2026-07-05-persona-walkthrough-audit.md](reports/audit/2026-07-05-persona-walkthrough-audit.md)
    — seven personas driven through both routes at both viewports via CDP,
    with a 14-item prioritized worklist. Headline: content now converts; the
    remaining friction is floating-chrome discipline (coach tips / entice
    bubble / sticky CTA competing for the same corners) and trust plumbing
    (commit-data freshness, résumé behavior consistency).
